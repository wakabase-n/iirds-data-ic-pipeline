# Pipeline Architecture: The Stepwise Deterministic Approach

本アーキテクチャの核心は、確率的な「AIの柔軟性」と、ハードウェア設計に求められる「プログラムの決定論（100%の型安全性）」の責務を完全に分離することにあります。LLMへの直接変換によるハルシネーションや構文破壊を防ぐため、処理プロセスを3つのフェーズと1つの中間フォーマットに分割して構築されています。

## System Flow

```text
 [ 各社ベンダーの非構造化仕様書 (PDF / Markdown / HTML) ]
 │
 ▼
【 Phase 1: LLM (パース・正規化エンジン) 】
 │ ・複雑なiiRDSやSKOSのオントロジー解釈をLLMから完全に排除。
 │ ・テキストからの「客観的ファクトと数式の抽出」のみに特化。
 │
 ▼
[ 中間フォーマット (Simple Normalized JSON) ]
 │ ・平坦なピンリスト、数値と数式の分離、サニタイズ済みのプレーンテキスト。
 │ ・AIと決定論的プログラムを繋ぐ「型安全な防波堤」として機能。
 │
 ▼
【 Phase 2: Python (データ品質監査・HitL) 】
 │ ・JSONスキーマに基づく数値型チェック、必須キーの網羅性チェック。
 │ ・ルール違反や不確かな抽出データのみを人間（HitL）のレビューへ隔離。
 │
 ▼
【 Phase 3: Python (iiRDS / SKOS 確定コンパイラ) 】
 │ ・外部辞書（skos_dictionary.json）を参照し、表記揺らぎを標準概念URIへ集約。
 │ ・100%確定論的なロジックでクラス・プロパティを付与し、グラフ構造を組み立て。
 │
 ▼
[ 100% 型安全な iiRDS Data IC (JSON-LD) ]
```

## Architectural Benefits

- **ハルシネーションの遮断**: 規格知識や危険度判定のロジックをLLMに持たせず、下流のPythonコード（Phase 3）で決定論的に処理するため、出力データにAI特有の揺らぎが混入しません。
- **保守性の向上**: ベンダーごとのフォーマット差異はPhase 1のプロンプトで吸収し、規格や出力形式の改訂はPhase 3のPythonコードで対応可能な疎結合設計です。
