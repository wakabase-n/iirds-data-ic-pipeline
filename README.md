# Compiled Documentation: iirds-data-ic-pipeline

> 🌐 **Read this in other languages:** [日本語 (Japanese)](README_ja.md)

A data integration pipeline that compiles technical documentation from "static PDFs for human reading" into "executable Data ICs" that directly drive design tools and simulators.

This repository provides a Minimum Viable Product (MVP) for verifying multi-supplier semiconductor specifications. By combining international standards—**AAS (IDTA 02004)**, **iiRDS**, and **W3C SKOS**—this pipeline deterministically generates a 100% type-safe knowledge graph (JSON-LD) from natural language specifications.

## 🌟 Core Architecture: Separating AI Flexibility and Determinism

Feeding unstructured datasheets directly into Large Language Models (LLMs) triggers probabilistic hallucinations and syntax corruption, which is completely unacceptable in zero-defect hardware design.

To solve this, our architecture decouples the process into three distinct phases, positioning **"strict intermediate format generation via prompts"** as the critical safeguard of the system.

1. **Phase 1: Fact Extraction (LLM)**
   A schema-driven prompt that strictly prohibits high-level ontological interpretation, extracting only objective facts and mathematical formulas.
2. **Phase 2: Quality Audit (LLM / HitL)**
   A rigorous prompt-based audit applied to the extracted data. It guarantees 100% accuracy and completeness before passing the data downstream.
3. **Phase 3: Deterministic Compiler (Python)**
   A deterministic script that binds standard SKOS concepts and compiles the data into a type-safe iiRDS Data IC (JSON-LD).

## 🚀 Pipeline Execution Flow

### 1. Fact Extraction and Intermediate Formatting (`prompts/`)

Execute the LLM using `prompts/10_prompt_buildc_mid_file` to extract facts from the `samples/input_datasheet`. The LLM's autonomous reasoning is strictly constrained to output `normalized_facts.json`, physically separating dynamic formulas (e.g., `0.8 * VCC`) from static numeric values.

### 2. Data Quality Audit (`prompts/20_prompt_audit_NDF`)

Apply the audit prompt to the generated intermediate format to verify consistency with the original text. This step ensures zero omissions and rule violations, protecting the downstream compiler from corrupted inputs.

### 3. Deterministic Compilation (`compiler/main.py`)

Run the Python compiler to build `samples/iirds_data_ic.jsonld` from the validated intermediate data. This process is 100% deterministic, utilizing `mapping_rules/skos_dictionary.json` to absorb and normalize vendor-specific terminology.

### 4. Multi-Output Projection to CAD/DRC (`projections/`)

Parse the single JSON-LD source of truth to automatically project formatted CSVs for ECAD pin/rating libraries and constraint rule decks for DRC engines—requiring zero manual transcription.

### 5. Logic Simulation via Neo4j (DRC for Documents)

Utilize the Cypher scripts in `neo4j/検証用クエリ` to execute pre-design verification on a Neo4j graph database. Before laying a single trace on a PCB, you can deterministically trace "Which safety interlocks are triggered if VCC fluctuates?" and pinpoint catastrophic risk paths (DANGER) in milliseconds.
